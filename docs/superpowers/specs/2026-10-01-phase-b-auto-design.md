# Фаза B: автоисправление при наборе — дизайн

## Context
Ручной режим (Insert / Super+Insert / Alt+Insert) работает. Пользователь хочет, чтобы слово, набранное не в той раскладке, исправлялось само, как в Punto Switcher. Главный риск — ложные срабатывания (идентификаторы, команды, пароли). Пользователь много работает в терминале.

Решения пользователя: осторожный автомат, выключенный в терминалах и редакторах кода (вариант C); определение языка — гибрид: триграммы + словарь-вето.

## 1. Поведение
- Срабатывает на **пробеле** после слова: стереть слово и пробел → переключить раскладку → напечатать слово и пробел. Не на Enter (сообщение уже ушло) и не на знаках препинания (зависят от раскладки).
- Не трогаем: слова короче 3 букв; с цифрами; со смешанным регистром внутри (`myVar`, `Pass1word`); слова из словаря текущего языка (вето); слова из списка исключений пользователя; любые слова в приложениях-исключениях.
- Insert сразу после автоисправления отменяет его и добавляет слово (как оно было набрано) в исключения; автомат его больше не трогает.
- Автомат **по умолчанию выключен**; README предупреждает о паролях из строчных букв.
- Ручной режим не меняется.

## 2. Модель и данные
- `tools/gen-model`: из `/usr/share/hunspell/{en_US,ru_RU}.dic` (словоформы через `unmunch`, если установлен hunspell-tools, иначе основы) считает частоты триграмм с маркерами начала/конца слова; пишет компактную таблицу `core/data/trigrams.bin` (коммитится, вшивается `include_bytes!`); печатает точность: доля пойманных ошибок и доля ложных срабатываний на обоих словарях.
- Решение (`core/src/auto.rs`, чистые функции):
  1. нажатия слова → символы в текущей и следующей раскладке (таблицы xkb из A2);
  2. язык раскладки — по её буквам (кириллица → ru, латиница → en);
  3. оценка — средний логарифм вероятности триграмм; исправляем, если другая раскладка лучше на `MARGIN` и сама не ниже `FLOOR`;
  4. вето: слово как набрано есть в словаре текущего языка → нет.
- Порог подбирается так, чтобы ложных срабатываний было не больше 0,5 %; закрепляется тестом.
- Словари для вето демон читает из `/usr/share/hunspell` при старте; нет словаря — вето выключено, предупреждение в журнале.

## 3. Активное окно и настройки
- Демон следит за `app_id` активного окна (`zcosmic_toplevel_info_v1` + `ext_foreign_toplevel_list_v1`) в Wayland-потоке. Риск: протокол может быть только для привилегированных клиентов — первая задача плана проверяет. Если недоступен — исключения по приложениям не работают, автомат переключается вручную из попапа.
- Исключения по умолчанию: `com.system76.CosmicTerm`, `Alacritty`, `kitty`, `org.wezfurlong.wezterm`, `foot`, `org.gnome.Console`, `code`, `codium`, `dev.zed.Zed`, `jetbrains-*` (префикс).
- Конфиг: `auto_enabled: bool` (false), `auto_excluded_apps: Vec<String>`, `auto_exceptions: Vec<String>`.
- Окно настроек: вкладки «Основные» и «Автоисправление» (переключатель, список приложений: удалить/добавить `app_id`, список слов: удалить).
- Попап: второй переключатель «Автоисправление».

## 4. Код
- `core/src/auto.rs` — модель, вето, решение. `core/src/engine.rs` — режим auto на пробеле, отмена → действие `AddException(String)`.
- `daemon` — словари, активное окно, запись исключений в конфиг.
- `applet` — вкладки настроек, переключатель в попапе.

## 5. Тесты
- `auto.rs`: контрольные слова (`ghbdtn`→да, `руддщ`→да, `hello`/`grep`/`ls`/`Pass1`→нет), вето, длина, цифры, регистр; порог точности.
- Движок: автоисправление на пробеле, отмена + исключение, исключённое приложение, выключенный автомат.
- Вручную: чат/браузер, терминал (не срабатывает), отмена и запоминание, пароль с цифрами.

## Результат spike «активное окно» (2026-10-01)
- Обычный клиент (демон) видит `ext_foreign_toplevel_list_v1` с `app_id` всех окон, но на `zcosmic_toplevel_info_v1.get_cosmic_toplevel` COSMIC не присылает никаких событий — состояние «активно» недоступно непривилегированным клиентам.
- Панель выдаёт аплету привилегированное подключение (`X_PRIVILEGED_WAYLAND_SOCKET`), если в `.desktop` стоит `X-HostWaylandDisplay=true` (так делают штатные app-list и input-sources).
- **Решение:** активное окно отслеживает аплет (привилегированное подключение, `zcosmic_toplevel_info_v1`) и передаёт `app_id` демону D-Bus-методом `SetActiveApp(s)`. Без аплета в панели исключения по приложениям не работают (как предусмотрено выше).
