# cosmic-ext-lang-switch — спецификация фазы A

## Context

На COSMIC (Pop!_OS 24.04, Wayland) нет аналога Punto Switcher. Существующие решения (punto-rs, gswitch, autoswitch) на COSMIC не проверены или прямо не поддерживаются, и все переключают раскладку эмуляцией хоткея. Делаем свой аплет с демоном: фаза A — ручное исправление по хоткею, фаза B (автомат) — отдельно, позже.

Уже согласовано: имя `cosmic-ext-lang-switch`, APP_ID `io.github.shagovAlexei.cosmic-ext-lang-switch`; вариант C (сначала A, потом B); права — пользователь в группе `input` + udev для uinput, демон `systemd --user`; хоткеи настраиваются; раздел 1 (архитектура) одобрен.

## Раздел 1: архитектура (одобрено)

Workspace: `core/` (lib, чистая логика), `daemon/` (`cosmic-ext-lang-switch-daemon`), `applet/` (`cosmic-ext-lang-switch`).
Демон: evdev reader (пассивно, без grab) → буфер keycode'ов → корректор (N× BackSpace → `zcosmic_keyboard_layout_v1.set_group(next)` → повтор тех же keycode'ов через uinput). D-Bus `io.github.shagovAlexei.CosmicExtLangSwitch`: `Enabled`, `CurrentLayout`, сигнал `Corrected`, `Toggle`, `ConvertSelection`.
Аплет: код раскладки в панели, попап с вкл/выкл, списком раскладок, тремя полями хоткеев. Конфиг — cosmic-config, демон следит через `watch_config`.

## Хоткеи по умолчанию (согласовано; клавиши Pause нет)

| Действие | По умолчанию |
|---|---|
| Исправить последнее слово | `Insert` |
| Исправить выделенное | `Alt+Insert` (не `Shift+Insert` — это системная «вставка») |
| Исправить фразу (до Enter) | `Super+Insert` (не `Ctrl+Insert` — это «копировать»), как в punto-rs |

Ограничение: без grab демон не глотает клавишу — `Insert` доходит до приложения и в LibreOffice/VS Code/терминале переключает режим замены. Для фазы A принимаем (так же у punto-rs); лечится позже через grab только хоткея (uinput-прокси), если будет мешать.

## Раздел 2: поток данных и защита

1. evdev `KEY_*` press → если печатная клавиша (буквы, цифры, пунктуация) без Ctrl/Alt/Super → в буфер `(keycode, shift)`; `BackSpace` удаляет последний элемент.
2. Граница слова: `Space`/`Enter`/`Tab` закрывают слово (слово остаётся «последним» до следующей печатной клавиши, чтобы Insert после пробела тоже работал — пробел повторяется в хвосте). Сброс буфера целиком: клик мыши (evdev `BTN_*` с любых указателей), стрелки/Home/End/PgUp/PgDn, любой аккорд с Ctrl/Alt/Super, смена раскладки извне.
3. Хоткей → корректор. Во время коррекции собственные uinput-события игнорируются (фильтр по устройству uinput), ввод пользователя в это окно буферизуется и не теряется.
4. Повторное нажатие хоткея сразу после коррекции — откат (обратно в исходную раскладку).

Защита:
- Демон не пишет нажатия ни в лог, ни на диск; буфер только в памяти, максимум 256 keycode'ов.
- Блокировка экрана: подписка на logind `Lock`/`Unlock` сигналы сессии (не `LockedHint` — COSMIC 1.0.9 его не обновляет) → буфер сброшен и чтение приостановлено до Unlock.
- `Enabled=false` из аплета → буфер не наполняется вообще.
- Детект поля пароля на Wayland недоступен → в фазе A полагаемся на ручной режим (ничего не исправляется без хоткея). В фазе B — исключения по app_id через `zcosmic_toplevel_info`.

## Раздел 3: обработка ошибок

- Нет доступа к `/dev/input` или `/dev/uinput` → демон стартует, `CurrentLayout` работает, свойство `Status = "no-input-access"`; аплет показывает иконку-предупреждение и подсказку «добавьте пользователя в группу input, перелогиньтесь».
- Протокол `zcosmic_keyboard_layout_v1` недоступен → коррекция отключена, статус `no-layout-protocol`.
- В `xkb_config` одна раскладка → хоткеи no-op; больше двух → «следующая» по кругу (как Punto: переключает на следующую).
- Устройство отключилось/подключилось → inotify на `/dev/input`, переоткрытие без рестарта.
- Демон упал → systemd `Restart=on-failure`; аплет при пропаже D-Bus имени показывает «демон не запущен».
- Флаг `--check` у демона: печатает ok/MISSING по каждому пункту (input, uinput, layout protocol, раскладки, logind) — первое, что просить в баг-репорте.

## Раздел 4: тестирование

- `core/`: юнит-тесты на чистые функции — наполнение/сброс буфера по последовательности событий, выбор хвоста для «слова» и «фразы», план коррекции (`Vec<Action>`: BackSpace×N, SetGroup, Key…), откат, парсинг хоткеев из конфига. Демон и аплет вызывают только эти функции.
- `just verify` = fmt + clippy `-D warnings` + `cargo test`.
- Ручная проверка на живой системе (TESTING.md): gedit/Text Editor, терминал COSMIC, Firefox, LibreOffice; ru↔en; слово, фраза, выделение, откат; блокировка экрана.
- Каждый найденный баг → именованный регрессионный тест + строка в таблице TESTING.md.

## Первая задача плана — spike «выделенное»

30 мин, код выбрасываемый: эмуляция `Ctrl+C` через uinput + чтение буфера обмена через data-control (`ext-data-control-v1` / `zwlr_data_control`, в cosmic-comp может требовать `COSMIC_DATA_CONTROL_ENABLED=1`). Если не работает без правки окружения — «исправить выделенное» уходит в фазу A2, слово/фраза не затронуты.

## Verification (для всей фазы A)

- `just verify` зелёный.
- `cosmic-ext-lang-switch-daemon --check` — все ok.
- В gedit набрать `ghbdtn`, `Insert` → `привет`, раскладка RU, индикатор в панели сменился; `Insert` ещё раз → откат.
- Заблокировать экран, разблокировать, `Insert` — ничего не исправляет (буфер сброшен).

## Результат spike «выделенное» (2026-09-30)

На этой системе `wl-paste --primary` без фокуса и без `COSMIC_DATA_CONTROL_ENABLED` читает выделенный текст (primary selection), значит data-control доступен. «Исправить выделенное» технически возможно без эмуляции Ctrl+C. В план фазы A не входит, делается отдельной задачей (A2): читать primary selection, стереть выделение (BackSpace), переключить раскладку, напечатать конвертированный текст (нужна таблица keycode по символам).
